What can a web page reach on your machine?

Any page you visit can run JavaScript that sends requests to 127.0.0.1 and localhost. The same-origin policy limits what it can read back, but the request can still arrive. This page measures what your browser lets through, from an ordinary HTTPS page, to a throwaway listener on your own machine.

Nothing runs until you click. Results stay on this page and are never sent anywhere. The page has no analytics, loads nothing from other sites, and reads nothing from its URL.

1. Start the canary

The canary is a listener from the localprobe repository. It runs on port 47823, logs each request it receives, holds no data, and exits after 10 minutes.

git clone https://github.com/orlenko/localprobe.git
cd localprobe
node src/cli.ts canary

Check that it is up: open http://127.0.0.1:47823/ in a new tab. You should see "localprobe canary", and the canary should log a line. If it does not, no result below means anything.

2. Run the tests

The page sends each request type to four addresses for the same canary: 127.0.0.1, localhost, [::1], and 0.0.0.0. Your browser may ask for permission to reach devices on your local network or apps on this device. Answer it either way, and note what you chose. A small window opens when you click and stays blank until the form test near the end. Leave it open. It closes itself.

Waiting for a click.

Paste this output next to the canary's log. Every request path carries the run ID, and the expected list shows which lines should appear. A request that never arrived has no line. The page reports only what it saw. A TypeError covers a refused connection, mixed content, a denied permission, and a blocked port, and the request may have arrived in some of those cases. For the iframe and form tests, the page cannot see inside the other window. They count only if the canary's own page sends back a message. Otherwise they read "no signal; see canary log".

3. Your own services

Type up to 20 port numbers. The page sends GET / to http://127.0.0.1:PORT/ for each, with no cookies, and reports the status and size if it could read the response, or "reachable" if the request completed but the response was hidden. A redirect is not followed when the page tries to read the response. If that fails, the page retries in no-cors mode, where browsers always follow redirects, so a service that redirects elsewhere sends your browser there. Response bodies are counted, never shown or kept.




A response this page could read, any other website can read too, unless your browser treats the two pages differently. The localprobe scan command tests the services themselves: CORS, preflight, Host checks, and bind address.



4. Revoke the permission afterwards


If your browser asked and you allowed it, the grant belongs to the whole https://orlenko.github.io origin, which every GitHub Pages site under that account shares. Remove it when you are done.


    
	
  • Chrome and other Chromium browsers: paste chrome://settings/content/siteDetails?site=https%3A%2F%2Forlenko.github.io into the address bar, then click Reset permissions, or set the local network entries back to "Ask".
    • 
	
  • Safari and Firefox: if the browser asked, remove orlenko.github.io from the matching permission in the browser's website settings.

Limits


    
	
  • This page is served over HTTPS. A hostile page can use plain HTTP, and browsers treat the two differently. Results for plain-HTTP pages are not measured.
    • 
	
  • Chrome flags 0.0.0.0 requests from an HTTPS page as mixed content. In the dated runs they still arrived when the permission was granted. The canary log shows whether anything arrived.
    • 
	
  • The canary logs TCP connections that send no request (IDLE, EMPTY), with the time each opened. A browser can connect to a port without sending a request.
    • 
	
  • A browser that blocks a request type on this date and version does not make any service safe. Browser rules change between releases.
    • 
	
  • Measured results, with dates and versions, are in the matrix. The design is in docs/design.md.
